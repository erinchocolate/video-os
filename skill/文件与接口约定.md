# 文件与接口约定

所有命令从工作区根目录执行，使用 `python -X utf8 scripts/video.py`。`--job` 是 `process/` 下面某条视频的目录；归档可能改名该目录，以命令返回值为准。命令中的“完整时间_标题”等表示要替换的真实路径。

## 任务文件

- `manifest.json`：原始文件名、完整拍摄时间、当前原片路径、处理目录、原片哈希、媒体信息和阶段状态。由脚本维护，不手工伪造完成或审核状态。
- `source_probe.json`：接收时的媒体元数据快照，可能包含历史路径；活动路径以 manifest 为准。
- `audio.wav`、`transcript_asr.json/.txt/.srt`、`逐字稿.md`、`review_flags.json`：原片转写及复核线索。
- `edit_spec.json`：agent 针对该视频编制的编辑判断；`edit_plan.json`、`剪辑稿_待确认.md` 由 review 生成。
- `approval.json`、`edit_plan_approved.json`：收到用户对具体剪辑稿的确认后生成。审核绑定原片与提案 SHA256。
- `render_plan.json`、`edited_audio.wav`、`edited/`：实际帧时间线、剪后音频和剪后转写。
- `caption_spec.json`：agent 的分句、重点词及有依据的识别校正。`final_subtitles.ass/.srt/.json` 和 `成片字幕稿.md` 由脚本生成。
- 按用户要求启用字幕审核时，`subtitle_review_request.json`记录required=true与用户原话；`subtitle-review`生成无字审核视频、字幕审核.html和字幕审核稿.md，`subtitle_review.json`绑定待审字幕哈希。`subtitle-approve`记录真实确认原话及相关文件指纹，未确认不得烧录或交付。该模式不自动适用于所有视频。
- `rendered.mp4`、`render_inputs.json`、各阶段日志、预览图、`verification.json`：渲染和验收证据。发布后视频进入 final，其余物料保留。

## 编辑判断输入：edit_spec.json

```json
{
  "summary": "描述视频主线和本次精简方向",
  "preserve": ["必须保留的观点或条件"],
  "cuts": [
    {"start": 12.3, "end": 13.1, "text": "准备删去的原话", "reason": "针对本句的删除理由", "kind": "speech"}
  ],
  "corrections": []
}
```

时间为原片秒数；每段满足 `0 ≤ start < end ≤ 原片时长`，不能删除整条视频。cuts 可为空。review 的可选 `--trim-pauses` 会将未与已有删段重叠的 ≥0.6 秒停顿列入提案，保留两侧各约 0.15 秒，也须用户审核。corrections 记录识别疑点，不自动修改音频。

## 字幕判断输入：caption_spec.json

```json
{
  "lines": [
    {"text": "实际剪后说出的第一句", "emphasis": "第一句"},
    {"text": "实际剪后说出的下一句"}
  ],
  "corrections": [
    {"from": "识别误词", "to": "校正文本", "reason": "实际复核依据", "near": 15.2}
  ]
}
```

lines 也可用字符串。横屏每行至多 16 字；竖屏按安全宽度缩短，1080×1920 默认使用 100 号字、每行至多 8 字。emphasis 必须是本行包含的连续字词，每句少量强调。去除标点后的全部字幕须与剪后词级转写对应，除非明确记录 corrections。near 是剪后秒数，区分重复出现的误词。不得用虚构校正掩盖遗漏或改写。

局部复核发现某行ASR起点包含过长静音时，可在该行增加start_override（剪后秒数）和timing_basis（实际试听或局部词级识别依据）。这只调整该行显示起点，不改文字或音频；必须早于本行话语结束，且仍通过至少0.5秒、无重叠及总时长校验。没有明确依据时使用默认对齐，不凭语义随意移动。

极短时间内含大量零时长、低置信度词的尾段会标为疑似识别幻觉；原始结果保留，字幕记录排除的段号。agent 必须复核标记，不能据此自动删除正常话语。

## 阶段状态

`ingested → transcribed → archived → awaiting_edit_approval → approved → edited → subtitles_ready → rendered_pending_verification → awaiting_visual_check → completed`

状态用于恢复，不授予新权限。记录与文件不一致时核对实际文件、日志和哈希，不直接将状态改为下一步。

## 发布包装与待上传

成片之后读 [video-package](video-package/SKILL.md)。package-prepare、package-build、package-feedback、package-refine、package-select、package-check、upload-ready、upload-check均经scripts/video.py使用同一个--job。旧资料用package-migrate迁入package。

包装输入与资产在package/materials，不继续写process/publishing；剪辑转写仍在process。输入格式见 [包装输入格式](video-package/references/input-formats.md)，尺寸来源见 [平台参考](video-package/references/platforms.md)。

发布选择.json记录用户原话、标题、说明、文字稿、精确封面目录和哈希；推荐或收藏不代替选择。upload_manifest.json与upload_verification.json留在package，upload只收五类材料。剪辑completed保持原义，包装状态另行记录。
