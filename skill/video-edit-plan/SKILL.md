# 编制剪辑稿与记录审核

输入：已归档任务的转写、词级时间点、silences.json 和复核标记。读 [输入格式](../文件与接口约定.md)。入口 `scripts/video.py review`、approve；实现 `scripts/video_pipeline/intake.py`。

## 内容判断

- 编制时先理清主线、结论、必要条件和必须保留的例子；对外呈现时先展示完整剪后文本，分析和细节放在后面。
- 优先精简无意义口头语、重复、重新起句和长停顿，不机械删除每个“就是”“然后”，不删除有意义的犹豫、强调或条件。
- 用词级时间点定位每段，写出原话、起止秒数和具体理由，避免密集短切。不能复制样片的删段到新视频。
- 粗剪要同时检查口头语和画面连续性：长转写可能吞掉重复起句或“嗯、啊”，必要时对用户标记处做关闭VAD的局部识别。重录间隙的转头、抬头、晃身、手势准备不能因短促噪声而残留成零点几秒的碎片；查看切点前后的连续抽帧，并结合音频和实际话语收紧边界，不能只按文字或静音阈值裁切。
- 在 edit_spec 的 pause_policy 中可显式设置 merge_noise_gap（0–0.1秒）、padding（0.04–0.2秒）、trim_empty_edges，以及 preserve_ranges（原片秒数区间）。该策略只是停顿候选，最终仍需 agent 按内容和画面检查；不得用统一极短留白去吞字。用户要求保留完整开头时，用 preserve_ranges 排除该范围的停顿裁切。
- 可能改变立场、因果或有效信息的删改，先列出供用户判断。机器边界不等于精确发音边界。

## 提案

采用两轮判断：先选出观点完整、表达自然的有效录次，再专门检查接缝。不要为了清除所有口头语制造密集碎切；少量有意义的停顿和语气词可以保留。对同一句多次重录，不默认最后一次最好，也不从不同录次拼接单词来凑句。

粗剪交给用户前，逐切点检查保留片段的句首、句尾：听是否残留“嗯、啊”、重复起音、吞字、呼吸截断或语气突变；连续查看切点两侧画面，检查头部、手部、身体和视线是否突然跳变，以及是否夹入无声转头、晃身或准备动作。按需要扩大上下文，不能用静音检测、转写结果或单帧截图代替听看。优先在完整句子或小段边界衔接；姿态差异无法自然解决时保留待复核标记，不靠删有效信息掩盖。

检查记录保存在本条process内，注明粗剪版本、切点在粗剪及原片的位置、实际采用的音频/连续画面检查方式、发现的问题、处理和未解决项。无法实际听音时明确标记未听校，把疑点交给用户，不写“已全部听看”。用户应主要审观点、表达和整体节奏，明显接缝问题尽量在交付前解决。定稿或返剪后重新核对受影响切点，旧检查不能直接沿用。

agent 将判断写入本任务 edit_spec.json，再执行：

```powershell
python -X utf8 scripts/video.py review --job "process/完整时间_标题" --spec "process/完整时间_标题/edit_spec.json" --trim-pauses
```

--trim-pauses 可选，仅把候选停顿加入提案，不会剪视频。阅读生成的 edit_plan.json 和剪辑稿，核对逻辑、删段和时长，向用户提供链接和主要删改。单条文字稿审核模式在此等待确认；默认批次模式继续执行 rough 生成未批准预览，通过 batch-review 展示粗剪和对应逐字稿，再等待用户确认该粗剪版本。

## 成果呈现顺序

- 剪辑稿标题之后直接放完整剪后文本，按语义整理标点和段落，保留实际话语；不要先堆叠状态、时长、分析、删段或处理过程。
- 完整文本之后再放预计时长和简短结论，最后列删改位置、原话、原因、识别疑点及技术依据，便于用户先读成品，有问题再查细节。
- 对话交付同样先呈现完整文本或可直接打开的成果，再说明修改及原因；不要只汇报做了什么，让用户到长篇细节末尾寻找成果。
- review 生成的可读稿若不符合此顺序，在展示前重排；只整理展示和标点时不改 edit_plan.json、删段或审核状态，也不把展示调整视为用户批准。

## 收到确认后

引用用户实际确认原话和 review 返回的 SHA256。批次或存在粗剪预览时，还必须提供 --rough-version（rough_current.json 的 version）；脚本核对当前提案、原片及预览文件哈希：

```powershell
python -X utf8 scripts/video.py approve --job "process/完整时间_标题" --plan-hash "当前提案SHA256" --message "用户实际确认原话"
```

产出 approval.json 与审核快照。不能把“先做样片”“沿用字幕”或上一条视频的认可当作新稿批准。初始化、edit、转写、render 不得自动制造确认。

提案更改后旧确认失效；重新展示并确认。验收：记录匹配当前原片和提案哈希，确认依据可追溯。
