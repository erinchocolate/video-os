# 批次处理与集中审阅

用户入口为 Inbox、review/审阅入口.html、upload。raw 始终保存完整原片。

## 接收与粗剪

录制准备建议（用户询问录制方法或准备下一批时提供，不作为接收素材的门槛）：说错后可保持录制，安静停两三秒，头、手和身体恢复自然位置，再从当前完整句子开头重说；依赖前文时重说当前小段，通常不用重录整条。避免只补单词或半句话，也避免边调整姿势边起句。保留正常表达中的自然动作，重点减少重录间隙的突然转头、晃身和手势准备。可选在开头报主题、结尾说“这条结束”并留几秒安静；这些标记不进入成片。素材未遵循这些建议时仍按实际内容处理。

1. 读转写、归档、剪辑稿 skill，核对 Inbox 和既有任务。`batch-create --batch 批次名` 固定本批成员；之后新放入 Inbox 的视频不自动混入本批。批次名只是管理标识，不冒充拍摄时间。
2. `batch-prepare --batch 批次名` 逐条 ingest 和 transcribe，失败记录原因并继续。可重跑，从 manifest 和真实文件恢复。本机 Python 别名不可用时用 `scripts/video.ps1` 替代 `python -X utf8 scripts/video.py`。
3. agent 阅读每条完整逐字稿与词级位置，独立编写 edit_spec；archive 后使用命令返回的新目录。批次清单可按原文件名找回归档后的任务，歧义时报错，不猜。
4. `review --job ... --spec ... [--trim-pauses]` 生成具体方案；`batch-rough --batch 批次名` 或 `rough --job ...` 生成未批准的可播放预览。此步骤不生成 approval，也不调用正式 edit/render/publish。
5. `batch-review --batch 批次名` 更新审片清单。确认粗剪的视频帧数、音画时长、解码通过及链接文件存在；检查关键切点画面。默认在预览导出后直接从粗剪音频重新机器转写；初始词级映射稿归入预览目录 history/mapped_transcript，明确标注机器识别不等于全片人工听校。转写中断可用 rough-transcribe --job 或 batch-transcribe-rough --batch 恢复，不重剪视频。

## 内容确认

集中交付粗剪前，按video-edit-plan逐切点做接缝复核并保存真实检查记录，重点覆盖重录边界、口头语残留和无声动作碎片。集中页列出仍需用户判断的位置及限制，不把基础切点清理全部留给用户找。

- 每条展示视频名、粗剪版本、视频和逐字稿链接、状态及疑问。同一批可以一次收多条反馈，必须分别落实到具体版本。
- 清单的文本框仅本机暂存，导出反馈文件或聊天意见才交给 agent；填写、收藏、导出均不自动批准。
- 用户确认后 `approve --job ... --plan-hash ... --rough-version ... --message 用户原话`。未知版本、旧稿、改变过的预览拒绝确认；不得把启动整批处理视为批准具体删改。
- 需要修改时记录用户反馈、更新 edit_spec/review，再生成新的粗剪版本。旧版保留；新版本必须重新确认。正式剪后物料的修订继续遵循 history 归档规则。
- 批次不会自动批准、烧录字幕或选择封面。通过的条目按 edit、剪后重新转写、字幕及交付 skill 继续；失败或返剪的条目不阻塞其余条目。

## 标题封面与上传

内容定稿后依据最终内容每条生成20组真实候选，集中在清单中链接包装总览。明确选择后执行 package-select、upload-ready、upload-check；新批次输出 upload/批次名/任务名/，旧交付不迁移、不覆盖。

`batch-review` 在已有发布包时同时生成“标题封面集中审阅.html”：同页展示每条标题和实际横竖封面，支持按视频、比例、建议起点及本机收藏筛选；导出的标题与封面偏好不是最终确认。移出本批的条目保留在batch.json的excluded_items及历史快照，original_number保留用户熟悉的编号。

## 验证

交付前执行 `batch-review --batch 批次名`、`batch-check --batch 批次名`，检查清单全部本机链接、每条原片/预览/逐字稿/时间线哈希及粗剪转写音频。记录在本批 batch_verification.json；失败条目必须明确说明原因，不能宣称整批就绪。

修改批次与审核逻辑后运行 `scripts/tests/test_batch.py`、`scripts/tests/test_workflow.py`、`scripts/tests/test_packaging.py`。测试使用隔离合成素材；不能替代真实视频的用户确认。

## 下一批的默认交接

审阅入口只列当前待处理批次；用户确认整批发布完成后，将batch.json的review_archived设为true并刷新入口，已完成批次单列到review/历史审阅.html。证据留在原批次目录以保持粗剪与反馈路径有效；不要移动或删除process引用的预览。用户只是审片通过时仍需选标题封面，不能提前归档。清理仅针对可重建且无引用的重复页面，先核对引用；保留时间线反馈、审核依据及精确选择记录。下一批使用新的批次目录，不复用旧反馈或旧浏览器收藏。

用户说“开始处理这批”后固定Inbox成员，一次准备整批粗剪；集中审片通过后完成字幕成片，再集中展示标题封面。标题、封面可分开选择；收到导出JSON及按选择打包的明确指令后逐条绑定版本，汇总到upload/批次/上传工作台.html。用户手动上传，明确告知完成后按video-package的归档步骤移到upload/published/批次。集中页始终反映真实阶段，移出的重复主题保留excluded_items，不删除原片。

导出反馈优先从用户实际提供路径读取；用户说已导出但未给路径时可检查Downloads最新的同名反馈，只读取相关文件并复制到本批review留证。不依赖上次聊天或临时cache脚本恢复。
